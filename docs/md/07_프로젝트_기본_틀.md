# 07 프로젝트 기본 틀

> 이 단계에서는 OOTD 쇼핑몰을 실행하고, 이후 화면과 기능을 구현할 수 있는 공통 구조를 준비한다.
> 공통 UI의 세부 구성은 08 문서, 화면별 기능은 09 문서, 데이터 연결과 저장 처리는 10 문서를 따른다.

---

## 7.1. 이번 단계의 목표

React 프로젝트가 정상적으로 실행되고, 정한 URL로 각 화면을 열 수 있으며,
모든 화면이 같은 레이아웃과 데이터 사용 규칙을 따를 수 있도록 기본 틀을 만든다.

이 단계의 산출물은 실행 환경, 폴더 구조, 페이지 연결, 공통 레이아웃,
기초 데이터와 공유 상태를 사용할 기반 코드이다. 상품 카드·검색·주문 등
화면별 세부 기능은 이 단계에서 구현하지 않는다.

## 7.3. 진행 순서

### 7.3.1. 실행 환경 확인

- `package.json`에 정의된 React 19, React Router 7, Vite 8 환경을 사용한다.
- 처음에는 `npm install`로 필요한 패키지를 설치한다.
- `npm run dev`로 개발 서버를 실행하고 `http://localhost:5175`에서 화면을 확인한다.
- 포트는 `vite.config.js`에서 5175로 고정한다(`strictPort`). 5173·5174는 다른 프로젝트가 사용한다.
- `npm run lint`와 `npm run build`로 코드 검사와 배포용 빌드가 가능한지 확인한다.
- Vite·rolldown·oxlint는 이 PC에서 실행되는 버전으로 고정하고 `npm update`로 올리지 않는다.
- 실행 방법과 사용 도구는 README에 함께 정리한다.

### 7.3.2. 페이지와 라우팅 준비

03 화면 정의 목록서에 정한 URL과 페이지 컴포넌트를 React Router로 연결한다.
홈, 의류 목록, 의류 상세, 장바구니, 주문서, 주문 완료, 주문 내역처럼
기본 구매 흐름에 필요한 화면이 주소로 열려야 한다.

| 화면 | 경로 | 페이지 파일 |
|---|---|---|
| S-01 홈 | `/` | `HomePage.jsx` |
| S-02 의류 목록 | `/products` | `ProductListPage.jsx` |
| S-03 의류 상세 | `/products/:productId` | `ProductDetailPage.jsx` |
| S-04 장바구니 | `/cart` | `CartPage.jsx` |
| S-05 주문서 | `/checkout` | `CheckoutPage.jsx` |
| S-06 주문 완료 | `/order-complete/:orderId` | `OrderCompletePage.jsx` |
| S-07 주문 내역 | `/orders` | `OrdersPage.jsx` |
| S-08 좋아요 목록 | `/wishlist` | `WishlistPage.jsx` |
| S-09 관리자 | `/admin`, `/admin/new`, `/admin/:productId/edit` | `AdminPage.jsx`, `AdminProductFormPage.jsx` |
| S-11 LISTS | `/lists` | `ListsPage.jsx` |
| S-12 재입고 알림 목록 | `/restock-alerts` | `RestockAlertsPage.jsx` |
| S-10 페이지 없음 | 그 밖의 주소(`*`) | `App.jsx`에서 직접 안내 |

경로는 `src/App.jsx` 한 곳에 모으고, 주소가 바뀌는 값(의류 번호, 주문 번호)은
`useParams`로 읽는다. 정의되지 않은 주소는 페이지 없음 안내를 표시한다.
추가 화면의 세부 동작은 09 화면별 기능 구현 문서에서 연결한다.

### 7.3.3. 공통 레이아웃 준비

모든 페이지가 같은 틀을 사용하도록 `Layout`을 만들고, 그 안에 헤더,
현재 페이지 내용, 푸터를 배치한다. 페이지 내용은 `Outlet` 자리에 들어간다.

- 헤더에서는 홈, 의류 목록, 목록(LISTS), 주문 내역, 장바구니로 이동할 수 있게 한다.
- 헤더 오른쪽 위 로고 옆에는 관리자 화면으로 가는 ADMIN 버튼을 둔다.
- 홈은 표지 이미지와 어울리도록 투명 헤더를 사용할 수 있게 한다(`transparentHeader`).
- 다른 화면은 기본 헤더와 같은 본문 여백(`container`)을 사용한다.
- 관리자 화면은 재입고 알림 팝업을 띄우지 않는 틀을 사용한다(`restockPopup={false}`).
- 공통 UI의 모양과 상세 동작은 08 공통 UI 문서에서 정한다.

### 7.3.4. 기초 데이터와 공유 상태 준비

의류와 카테고리의 기본 데이터는 `mocks`의 JavaScript 파일에서 불러온다.
여러 화면에서 함께 써야 하는 데이터는 Context를 기준으로 관리하고,
`src/main.jsx`에서 아래 순서로 앱 전체를 감싼다.

```
ProductsProvider          의류와 사이즈별 재고
  └ CartProvider          장바구니 (의류 정보를 붙여야 하므로 안쪽에 둔다)
     └ OrdersProvider     주문 내역
        └ WishlistProvider        좋아요 목록
           └ RestockAlertsProvider 재입고 알림 신청
```

- 의류와 재고
- 장바구니
- 주문 내역
- 좋아요 목록
- 재입고 알림 신청

화면 안에서만 잠깐 필요한 검색 입력, 선택 사이즈, 열린 메뉴, 배송 정보 입력은
해당 화면의 state로 관리한다. 검색어·브랜드·계절·분류·정렬처럼 새로고침해도
유지되어야 하는 탐색 조건은 주소 쿼리에 담는다. 각 데이터의 구조와 Context별
역할은 05와 10 문서를 따른다.

### 7.3.5. 저장·불러오기 기반 준비

운영 데이터는 브라우저의 localStorage에 저장해 같은 브라우저에서 새로고침 후에도
유지되게 한다. localStorage 접근은 화면에서 직접 처리하지 않고 공통 저장 도우미와
Context를 통해 처리한다.

`src/utils/storage.js`에 아래 함수를 두고 모든 Context가 같은 방식으로 쓴다.

| 함수 | 역할 |
|---|---|
| `readStorage` | 읽고 JSON 변환·구조 검사까지 한 뒤 값과 실패 여부를 함께 돌려준다 |
| `writeStorage` | 하나를 저장하고 성공 여부를 돌려준다 |
| `writeStorageAll` | 여러 키를 한 번에 저장하고, 실패하면 이미 쓴 값을 되돌린다 |
| `clearStorage` | 사용자가 초기화를 확인했을 때만 지운다 |

- 처음 접속하여 저장된 값이 없으면 기본값 또는 빈 목록으로 시작한다.
- 저장값을 읽지 못하거나 구조가 맞지 않으면 기존 값을 바로 지우지 않는다.
- 변경할 데이터는 먼저 저장하고, 저장에 성공한 경우에만 화면의 확정 상태를 바꾼다.
- 사용자가 초기화를 선택하고 확인한 경우에만 해당 저장 데이터를 지운다.

저장 키, 구조 검사, 여러 데이터를 함께 저장하는 방식은 10 화면과 데이터 연결 문서에서
구체적으로 정리한다.
