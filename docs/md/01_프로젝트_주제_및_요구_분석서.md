# 01 프로젝트 주제 및 요구 분석서

> 여기서 정한 요구사항 번호(`R-00`)는 02 기능 명세서, 03 화면 정의 목록서, 11 테스트 체크리스트에서 그대로 사용합니다.

## 1.1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | OOTD |
| 서비스 주제 | 의류 구매 쇼핑몰 |
| 개발 형태 | 리액트 기반 프런트엔드 웹 애플리케이션 |
| 판매 대상 | 의류를 구매하려는 일반인 |
| 주요 사용자 | 원하는 의류를 검색하거나 브랜드별·종류별로 살펴보고 구매하려는 일반인 |
| 서비스 목적 | 의류 정보를 확인하고, 구매할 의류를 장바구니에 모아 주문한 뒤 주문 내역을 확인할 수 있도록 한다. |
| 학습 목표 | 리액트 수업에서 배운 컴포넌트, props, state, 이벤트, 리스트·조건부 렌더링, 폼 처리를 연결하여 구현한다. |

OOTD는 일반 구매자가 이용하는 의류 구매 쇼핑몰이다. 의류 정보는 미리 준비한 mock 데이터와 이미지 파일로 제공하며, 사용자는 별도의 회원가입 없이 상품 탐색과 모의 주문을 진행한다.

## 1.2. 대상 사용자

| 사용자 상황 | 필요한 점 |
|---|---|
| 사고 싶은 의류의 상품명이나 브랜드, 의류 종류를 알고 있다. | 상품명, 브랜드 또는 의류 종류로 원하는 의류를 찾을 수 있어야 한다. |
| 특정 의류를 정하지 않고 관심 브랜드나 의류 종류로 의류를 찾는다. | 브랜드별·종류별 의류 목록을 살펴볼 수 있어야 한다. |
| 구매 전에 의류에 관한 정보를 확인하려 한다. | 의류 종류, 착용 계절, 사이즈, 권장 성별, 의류 사진을 확인할 수 있어야 한다. |
| 여러 의류를 한 번에 구매하려 한다. | 구매할 의류를 사이즈별로 장바구니에 모으고 수량과 금액을 확인할 수 있어야 한다. |
| 주문한 내용을 다시 확인하려 한다. | 완료된 주문의 의류, 사이즈, 수량, 금액을 확인할 수 있어야 한다. |

### 주문·금액 기준

| 항목 | 기준 |
|---|---|
| 사이즈 | 의류마다 사이즈 하나를 선택해야 장바구니에 담을 수 있다. |
| 수량 | 1~99의 정수. 같은 의류·같은 사이즈는 수량을 합산하며 99를 넘을 수 없다. |
| 장바구니 금액 | 의류의 현재 가격(할인이 있으면 할인 가격)으로 계산한다. |
| 주문 금액 | 주문할 때의 의류명·사이즈·가격(할인 적용)·수량을 주문 내역에 저장하며, 이후 가격이나 할인율이 바뀌어도 변하지 않는다. |
| 주문 범위 | 장바구니 전체를 주문하며, 배송비는 0원이다. |
| 재고 | 사이즈별로 관리한다. 품절된 사이즈는 담을 수 없고, 주문하면 재고가 줄어든다. (추가 기능 구현 시) |

## 1.7. 주요 사용자 시나리오

### 의류 검색부터 주문 완료까지

1. 사용자가 OOTD에 접속하여 의류 목록을 확인한다.
2. 상품명이나 의류 종류, 브랜드를 검색하거나, 브랜드·종류를 선택한다.
3. 원하는 의류를 선택하여 상세 정보(종류, 착용 계절, 사이즈, 권장 성별, 사진)를 확인한다.
4. 사이즈와 구매 수량을 선택하고 장바구니에 담는다.
5. 장바구니에서 구매할 의류, 사이즈, 수량, 금액을 확인한다.
6. 주문서에서 주문 내용과 최종 금액을 확인하고 배송 정보를 입력한다.
7. 서비스가 입력값을 검사하고 모의 주문을 완료한다.
8. 서비스가 주문 내역을 저장하고 주문한 항목을 장바구니에서 제거한다.
9. 사용자가 주문 내역에서 방금 주문한 내용을 확인한다.

### 품절 사이즈 재입고 알림 (추가 기능)

1. 사용자가 의류 상세 화면에서 원하는 사이즈가 품절된 것을 확인한다.
2. 사용자가 품절된 사이즈에 재입고 알림을 신청한다.
3. 관리자가 관리자 페이지에서 해당 의류의 사이즈 재고를 입고한다.
4. 사용자가 사이트를 이용하면 재입고 알림 팝업창이 나타난다.
5. 사용자가 팝업에서 의류를 확인하고 장바구니에 담는다.
