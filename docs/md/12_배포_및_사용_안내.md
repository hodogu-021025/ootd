## 12.1. 준비

| 항목 | 값 |
|---|---|

| 개발 서버 주소 | http://localhost:5175 (5173·5174는 다른 프로젝트가 사용) |

처음 받은 폴더라면 `npm install`을 먼저 실행한다. 버전이 고정된 Vite·rolldown·oxlint는 `npm update`로 올리지 않는다(이 PC의 보안 설정 때문에 최신 버전이 실행되지 않는다).

## 12.2. 배포 순서

1. **검사**: `npm run lint` — 오류가 없어야 한다.
2. **테스트**: 11 테스트 체크리스트를 확인한다.
3. **빌드**: `npm run build` — `dist` 폴더가 만들어진다.
4. **확인**: `npm run preview` — 빌드 결과를 브라우저에서 확인한다(주소는 실행할 때 표시된다).
5. **올리기**: `main` 에 커밋을 올린다. GitHub Actions(`.github/workflows/ci.yml`)가 `npm run lint`·`npm run build` 를 다시 확인하고, `Dockerfile` 로 nginx 이미지를 만들어 `ghcr.io/hodogu-021025/ootd` 에 올린다.
6. **서버 반영**: 서버에서 `docker compose pull ootd && docker compose up -d ootd` 로 새 이미지를 받아 띄운다. 앞단 Caddy 가 HTTPS 를 맡는다.
7. **주소 확인**: https://ootd.hdg3383.com 에 들어가 12.4의 항목을 확인한다.

## 12.3. 새로 고친 내용을 올릴 때

1. 바뀐 파일을 팀과 공유하고 `backup`에 이전 버전을 남긴다(06 작업 규칙).
2. `npm run build`를 다시 실행한다. `dist`는 매번 새로 만들어지므로 이전 파일을 지울 필요는 없다.
3. `npm run preview`로 확인한 뒤 `main` 에 올리고 12.2 의 6번으로 서버에 반영한다.
4. 06 문서의 변경 기록 표에 날짜와 내용을 적는다.

## 12.4. 배포 후 확인

- [x] 홈 → 의류 목록 → 상세 → 장바구니 → 주문서 → 주문 완료 → 주문 내역 흐름이 이어진다
- [x] 사진이 모두 보인다(사진은 빌드 때 이름이 바뀌므로 특히 확인한다)
- [x] 주소를 직접 입력해도 화면이 열린다 (`/products/1`, `/orders`, `/admin`)
- [x] 새로고침해도 장바구니·주문 내역이 남아 있다
- [x] 브라우저 콘솔에 오류가 없다

> **주소를 직접 입력해도 열리는 이유**: 페이지 이동을 브라우저 주소로 처리하는 구조라, 파일이 없는 주소는 모두 `index.html`로 보내 주어야 한다. 이미지 안의 nginx(`nginx.conf`)가 이렇게 돌려준다. 이름에 해시가 붙는 `assets/` 파일은 오래 캐시하고, 나머지는 늘 새로 확인하게 해서 다시 배포하면 바로 바뀐다.

## 12.5. 사용 안내

- **로그인 없이** 모든 기능을 쓸 수 있다. 회원 가입과 결제는 이 프로젝트의 범위가 아니다.
- 주문은 **모의 주문**이다. 실제 결제·배송은 일어나지 않으며, 배송 정보를 확인하고 주문 내역에 저장하는 것까지만 한다.
- 장바구니·주문 내역·좋아요·최근 검색어·재입고 알림·관리자가 바꾼 의류 정보는 **그 브라우저에만** 저장된다. 다른 브라우저나 다른 기기에서는 보이지 않는다.
- 관리자 화면은 `/admin`이며 헤더의 **ADMIN** 버튼으로도 들어간다. 로그인이 없으므로 누구나 들어갈 수 있다(수업 과제 범위).
- 데이터를 처음 상태로 되돌리려면 브라우저 개발자 도구(F12) → Console에서 `localStorage.clear()` 후 새로고침한다.
- 화면은 PC 기준으로 만들었다. 모바일 대응은 이번 범위에 넣지 않았다.

## 12.6. 자주 겪는 문제

| 증상 | 원인·해결 |
|---|---|
| `npm run dev`가 포트 오류로 멈춘다 | 5175 포트를 이미 쓰고 있다. 그 프로그램을 끄고 다시 실행한다(포트는 바꾸지 않는다) |
| 사진이 보이지 않는다 | `src/image`에 파일이 있는지, `src/mocks/images.js` 등록표에 이름이 있는지 확인한다 |
| 담기·주문이 되지 않고 검은 안내 줄이 떠 있다 | 저장 데이터가 손상된 상태다. 안내 줄의 초기화를 확인한다 |
| 관리자에서 바꾼 내용이 사라졌다 | `localStorage.clear()`를 실행했거나 다른 브라우저로 열었다. 의류 데이터는 브라우저에만 저장된다 |
| 빌드가 실패한다 | 버전이 고정된 패키지가 바뀌지 않았는지 `package.json`을 확인한다 |
