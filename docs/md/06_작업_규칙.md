# 06 작업 규칙

> 이 문서는 파일·코드·데이터를 다루는 공통 규칙입니다. 규칙을 바꾸면 이 문서를 먼저 고치고 팀에 공유합니다.
> 기능 번호(`F-00`)는 02 기능 명세서, 화면 번호(`S-00`)는 03 화면 정의 목록서, 데이터 이름은 05 데이터 정의서를 따릅니다.

---

## 6.1. 폴더 구조

| 폴더·파일 | 담는 것 |
|---|---|
| `docs/md` | 01~12 문서의 마크다운 원본. 문서에 넣는 그림은 `docs/md/images` |
| `docs/docx` | 같은 문서의 Word 변환본. 04 와이어프레임은 팀원이 만든 Word 파일을 그대로 둔다 |
| `backup` | 원본 이미지(`original-images`), 받은 자료, 이전 버전 파일 |
| `public` | 빌드 때 그대로 복사되는 파일 (파비콘 `ootd_logo.png`) |
| `src/pages` | 화면 단위 컴포넌트 (S-01~S-12) |
| `src/components` | 여러 화면이 함께 쓰는 공통 UI |
| `src/context` | 여러 화면이 함께 쓰는 데이터와 그 변경 함수 |
| `src/mocks` | 기초 데이터 (의류·카테고리·사진 등록표·주문 상태 이름) |
| `src/utils` | 저장·금액·정렬 같은 계산 도우미 |
| `src/styles` | 전역 스타일 `global.css` |
| `src/image` | 화면에서 쓰는 이미지 (webp). 받은 상품 사진은 `src/image/products` |

## 6.2. 파일·이름 규칙

| 대상 | 규칙 | 예시 |
|---|---|---|
| 화면·컴포넌트 파일 | 파스칼케이스 `.jsx` | `ProductListPage.jsx`, `ProductCard.jsx` |
| 스타일 파일 | 같은 이름 + `.module.css` | `ProductCard.module.css` |
| 데이터·도우미 파일 | 카멜케이스 `.js` | `products.js`, `storage.js` |
| 컴포넌트 이름 | 파일 이름과 같게, 기본 내보내기 | `export default ProductCard` |
| 변수·함수 | 카멜케이스, 동작은 동사로 시작 | `selectedSize`, `handleAddToCart` |
| 상수 | 대문자 + 밑줄, 파일 위쪽에 모아 둔다 | `PAGE_SIZE`, `MAX_QUANTITY` |
| 이미지 | 소문자 + 밑줄 + 번호, webp | `women_01.webp`, `men_05.webp` |
| 저장 키 | `ootd_` + 소문자 이름 | `ootd_cart`, `ootd_restock_alerts` |

## 6.3. 코드 규칙

- 들여쓰기는 공백 4칸, 문자열은 작은따옴표를 쓴다.
- 주석은 한국어로, **무엇을 왜 그렇게 했는지**를 짧게 적는다. 코드를 그대로 옮겨 적지 않는다.
- 한 파일에는 한 화면 또는 한 컴포넌트만 둔다. 화면 안에서만 쓰는 작은 컴포넌트는 같은 파일 위쪽에 둘 수 있다.
- 수업에서 배운 것만 쓴다: 컴포넌트·props·state·이벤트·목록/조건 렌더링·폼·React Router·`useState`·`useEffect`·`useRef`·localStorage.
- 여러 화면이 함께 쓰는 데이터는 Context로 공유한다(팀 합의). 그 밖의 값은 화면의 state로 둔다.
- 화면 이동은 `Link`·`NavLink`를 기본으로 하고, 저장 후 이동처럼 눌러서 이동할 수 없는 경우에만 `useNavigate`를 쓴다.
- 목록의 `key`는 데이터의 고유 값을 쓴다(의류 번호, `의류번호-사이즈` 등). 순서만으로 만든 값은 쓰지 않는다.
- 새 패키지는 설치하지 않는다. 필요하면 먼저 팀에 이야기한다.

## 6.4. 스타일 규칙

- 컴포넌트마다 CSS Module 파일을 두고, 전역 스타일은 `src/styles/global.css`에만 둔다.
- 색은 `global.css`의 변수만 쓴다: `--color-primary` `--color-text` `--color-muted` `--color-bg` `--color-bg-sub` `--color-border` `--color-like`.
- 화면은 흑백으로 만든다. 빨간색(`--color-like`)은 **좋아요 하트**와 **장바구니의 "재고가 없습니다."** 두 곳에만 쓴다.
- 헤더 높이가 필요한 곳은 `--header-height` 변수를 쓴다(위에 붙는 요소의 기준).
- 내용의 가로 폭은 `container` 클래스를 쓴다. 화면 전체를 채우는 영역에는 쓰지 않는다.

## 6.5. 데이터 규칙

- 기초 데이터는 `src/mocks`의 `.js` 파일에 객체 배열로 두고 named export/import로 쓴다. JSON 파일은 만들지 않는다.
- import한 기초 데이터는 직접 바꾸지 않는다. 정렬·필터는 복사본(`[...products]`)으로 한다.
- 운영 데이터(장바구니·주문·좋아요·최근 검색어·재입고 알림·의류 변경)는 localStorage에 저장한다. 키와 구조는 05 문서를 따른다.
- localStorage는 화면에서 직접 쓰지 않고 `utils/storage.js`와 Context의 함수를 통해서만 읽고 쓴다.
- **먼저 저장하고, 성공했을 때만 화면 상태를 바꾼다.** 실패하면 이전 상태를 유지하고 이유를 안내한다.
- 의류 번호는 저장해 둔 "다음 번호"에서 가져오고, 한 번 쓴 번호는 다시 쓰지 않는다.

## 6.6. 화면 만드는 순서

1. 03 화면 정의 목록서에서 그 화면의 표시·동작·화면 상태를 확인한다.
2. 필요한 데이터를 05 데이터 정의서에서 확인한다(없으면 문서를 먼저 고친다).
3. 화면을 만들고 `npm run dev`(5175 포트)로 눈으로 확인한다.
4. 정상 동작뿐 아니라 **빈 목록·입력 오류·저장 실패** 화면 상태까지 확인한다.
5. `npm run lint`를 돌려 오류가 없는지 본다.
6. 11 테스트 체크리스트의 해당 줄에 표시한다.

## 6.7. 파일 공유·백업·변경 기록

Git과 GitHub는 수업에서 다루지 않으므로 쓰지 않는다. 대신 아래 방법으로 관리한다.

| 상황 | 방법 |
|---|---|
| 기준 폴더 | `C:\p_frontend` 를 기준으로 하고, 폴더 구조를 바꾸지 않는다 |
| 파일 공유 | 바꾼 파일만 압축해 카카오톡으로 주고받고, 받은 파일은 `backup`에 먼저 보관한 뒤 반영한다 |
| 백업 | 큰 작업(데이터 교체, 구조 변경) 전에 `src` 폴더를 통째로 복사해 `backup`에 날짜 이름으로 남긴다 |
| 이미지 원본 | webp로 바꾸기 전 원본은 `backup/original-images`에 보관하고, 쓰지 않는 원본은 `src/image`에서 지운다 |
| 변경 기록 | 아래 6.8의 표에 날짜와 내용을 한 줄씩 적는다 |
| 같은 파일 동시 수정 | 같은 파일을 두 명이 고치지 않는다. 담당 화면을 나누고, 공통 파일은 고치기 전에 알린다 |

## 6.9. 실행·검사 명령

| 명령 | 역할 |
|---|---|
| `npm install` | 패키지 설치 (처음 한 번) |
| `npm run dev` | 개발 서버 실행 (http://localhost:5175) |
| `npm run lint` | 코드 검사 |
| `npm run build` | 배포용 `dist` 폴더 만들기 |
| `npm run preview` | 빌드 결과 확인 |

개발 서버는 **5175 포트**만 쓴다. 5173·5174는 다른 프로젝트가 쓰고 있어 `vite.config.js`에서 5175로 고정해 두었다.
