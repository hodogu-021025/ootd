# 05 데이터 정의서

> 속성명과 저장 키는 07~10 구현에서 그대로 사용합니다. 바꾸면 관련 화면, mock 데이터, 검증 규칙을 함께 고칩니다.
> 기능 번호(`F-00`)는 02 기능 명세서, 화면 번호(`S-00`)는 03 화면 정의 목록서를 따릅니다.
> 이 문서는 구현된 코드(`src/mocks`, `src/context`, `src/utils`)의 내용과 같게 유지합니다.

---

## 5.1. 데이터 설계 범위

| 데이터 | 역할 | 원본·저장 위치 |
|---|---|---|
| 의류 카테고리 | 성별별 대분류 › 중분류 › 세부 항목 | `src/mocks/categories.js` |
| 의류 | 목록·상세에 표시할 기초 정보와 재고 | `src/mocks/products.js` → localStorage `ootd_products` |
| 상품 사진 등록표 | 사진 이름으로 실제 사진 파일을 찾는 표 | `src/mocks/images.js` |
| 주문 상태 이름 | 주문 완료·배송중·배송 완료·주문 취소 | `src/mocks/orders.js` |
| 장바구니 항목 | 구매할 의류 ID·사이즈·수량 | localStorage `ootd_cart` |
| 주문 | 완료·취소된 구매 내용과 배송 정보 | localStorage `ootd_orders` |
| 좋아요 ID | 좋아요한 의류 목록 (F-16) | localStorage `ootd_wishlist` |
| 최근 검색어 | 최근 검색어 목록 (F-20) | localStorage `ootd_recent_searches` |
| 재입고 알림 신청 | 알림 신청 목록 (F-28·F-29) | localStorage `ootd_restock_alerts` |
| 탐색 조건 | 검색어, 브랜드·계절·분류 필터, 정렬 | 주소 쿼리 문자열 |
| 화면 상태 | 선택 사이즈·수량, 배송 입력, 팝업 열림 등 | 리액트 state |

기초 데이터는 `.js` 파일에 객체 배열로 선언하고 named export/import로 사용한다. JSON 파일은 만들지 않는다. 회원·서버 데이터는 없다.

의류 데이터는 관리자 기능(F-23~F-26)과 재고(F-27) 때문에 localStorage에도 저장한다. 저장값이 있으면 그것을, 없으면 mock 데이터를 사용한다.

## 5.2. 의류 카테고리 — CATEGORY

성별마다 분류가 다르므로 배열 3개를 따로 둔다. 대분류(`category`) 안에 중분류(`groups`), 중분류 안에 세부 항목(`items`)이 있다.

| 항목명 | 자료형 | 필수 | 예시 | 설명 |
|---|---|---|---|---|
| `name` | string | 필수 | 상의 | 대분류 이름 (의류의 `category`와 같은 값) |
| `groups` | array | 필수 | 아래 | 중분류 목록 |
| `groups[].name` | string | 필수 | 티셔츠 | 중분류 이름 (의류의 `group`) |
| `groups[].items` | array of string | 필수 | `['반소매', '긴소매']` | 세부 항목 (의류의 `item`). 없으면 빈 배열 |

```js
export const menCategories = [
    {
        name: '상의',
        groups: [
            { name: '티셔츠', items: ['반소매', '긴소매', '카라', '후드티'] },
            { name: '니트', items: ['반소매', '긴소매', '카라'] }
        ]
    }
    // 아우터 · 하의 · 악세사리가 이어진다
];
```

- 대분류는 세 성별 모두 **상의 · 아우터 · 하의 · 악세사리** 4개다. 신발은 취급하지 않는다.
- 공용(`unisexCategories`)의 악세사리에는 모자·주얼리·잡화가 있다.
- 브랜드와 계절은 별도 배열을 만들지 않고 의류 데이터의 `brand`·`season` 값에서 뽑아 필터 목록으로 쓴다.
- 필터를 걸지 않은 상태는 주소에 값을 넣지 않는 것으로 표현한다('전체'라는 저장값을 두지 않는다).

## 5.3. 의류 — PRODUCT

| 항목명 | 자료형 | 필수 | 예시 | 설명·검증 규칙 |
|---|---|---|---|---|
| `id` | number | 필수 | 1 | 의류 고유 번호, 중복 금지. `/products/:productId`에 사용. 한 번 쓴 번호는 다시 쓰지 않는다 |
| `createdAt` | string | 필수 | `2026-06-25` | 등록일(YYYY-MM-DD). 관리자 목록에 표시한다 |
| `imageName` | string | 필수 | `women_01` | 사진 이름. `mocks/images.js` 등록표에 있어야 한다 |
| `brand` | string | 필수 | 미쏘 | 브랜드, 검색·필터 대상 |
| `name` | string | 필수 | 빈티지 리본 레이스 탑 | 상품명, 검색 대상. 공백만 있는 값 금지 |
| `price` | number | 필수 | 27000 | 정가, 0 이상의 정수 |
| `discountRate` | number | 필수 | 20 | 할인율, 0~90의 정수. 할인 없으면 0 |
| `type` | string | 필수 | 상의 | 의류 종류. 대분류와 같은 값을 넣는다 |
| `category` | string | 필수 | 상의 | 대분류. 그 성별 카테고리에 있는 이름 |
| `group` | string | 필수 | 블라우스 | 중분류 |
| `item` | string | 필수 | 프릴 | 세부 항목. 중분류에 세부 항목이 없으면 빈 문자열 |
| `season` | string | 필수 | 봄·여름 | 착용 계절. `봄·여름` `봄·가을` `가을·겨울` `사계절` 중 하나 |
| `sizes` | array of string | 필수 | `['S','M','L','XL']` | 판매 사이즈 목록, 최소 1개. 표시 순서대로 적는다 |
| `stock` | object | 필수 | `{ S: 4, M: 16 }` | 사이즈별 재고(0 이상의 정수). `sizes`의 모든 사이즈에 값이 있어야 한다 |
| `restockedAt` | object | 선택 | `{ M: '2026-09-21 10:08' }` | 사이즈별 재입고 일시. 재입고된 적이 없으면 없거나 빈 객체 |
| `gender` | string | 필수 | `women` | 권장 성별. `men` `women` `unisex` |
| `description` | string | 필수 | 레이스 브이넥과… | 상세 화면 설명 |

### 사이즈와 재고

판매 사이즈는 `sizes` 배열, 재고는 `stock` 객체로 나누어 관리한다. 재고 확인은 `product.stock[size]`, 재고 변경은 `{ ...product.stock, [size]: 새 값 }`으로 처리한다.

| 종류 | 사이즈 값 |
|---|---|
| 상의 · 아우터 · 하의 | `S` `M` `L` `XL` |
| 악세사리 | `FREE` |

| 재고 | 상태 | 화면 표시 (F-27) |
|---|---|---|
| 4개 이상 | 정상 | 사이즈만 표시 |
| 1~3개 | 재고 부족 | 재고 부족(N개 남음) |
| 0개 | 재고 없음 | 재고 없음, 선택 불가, 사이즈 아래에 재입고 알림 신청 제공 |

모든 사이즈가 0이면 상세 화면에 '품절'을 표시하고 담기 버튼을 쓸 수 없게 한다. 한 항목의 수량 한도는 99와 재고 중 작은 값이다.

### 권장 성별 저장값

저장값은 소문자로 두고, 화면에 보여 줄 때만 대문자 이름으로 바꾼다.

```js
export const genderLabels = { men: 'MEN', women: 'WOMEN', unisex: 'UNISEX' };
```

홈(S-01)의 배너는 `/products?gender=men` 형태로 이동하고, 목록(S-02)은 이 값으로 걸러낸다.

### 사진

사진 파일 경로는 빌드할 때마다 달라지므로 저장하지 않는다. 의류에는 **사진 이름만** 두고, 화면에서 등록표로 실제 사진을 찾는다.

```js
// src/mocks/images.js
import women01 from '../image/women_01.webp';

export const productImages = { 'women_01': women01 /* … */ };
export const productImageNames = Object.keys(productImages);
export function getProductImage(imageName) { return productImages[imageName]; }
```

- 사진은 모두 webp 파일이며 `src/image`(받은 상품 사진은 `src/image/products`)에 둔다. 원본은 `backup`에 보관한다.
- 관리자 등록·수정(S-09)에서는 `productImageNames` 중에서 고른다. 파일 업로드는 없다.

### 계산하는 값 (저장하지 않음)

| 값 | 계산 방법 |
|---|---|
| 판매 가격 | `Math.floor(price * (100 - discountRate) / 100)` |
| 항목별 금액 | 판매 가격 × 수량 |
| 주문 상품 금액 | 항목별 금액의 합계 |
| 최종 금액 | 주문 상품 금액 + 배송비(항상 0) |

### mocks/products.js 샘플

```js
export const mockProducts = [
    {
        id: 1,
        createdAt: '2026-06-25',
        imageName: 'women_01',
        brand: '미쏘',
        name: '빈티지 리본 레이스 탑',
        price: 27000,
        discountRate: 0,
        type: '상의',
        category: '상의',
        group: '블라우스',
        item: '프릴',
        season: '봄·여름',
        sizes: ['S', 'M', 'L', 'XL'],
        stock: { S: 4, M: 16, L: 12, XL: 16 },
        gender: 'women',
        description: '레이스 브이넥과 가운데 리본 끈이 사랑스러운 화이트 탑.'
    }
    // …
];
```

현재 87개(여성 36 · 남성 27 · 공용 24)이며 모두 가상 상품이다. 번호 순서가 등록순 기본 정렬이다. 한 페이지 12개씩 나누므로 성별마다 여러 페이지가 나온다.

### named import로 사용하기

```js
import { mockProducts, genderLabels } from '../mocks/products';
import { menCategories, womenCategories, unisexCategories } from '../mocks/categories';
```

import한 배열은 공통 기초 데이터이므로 직접 수정하지 않는다. 정렬할 때는 `[...products].sort(...)`처럼 복사본을 쓴다. 기초 데이터를 가져올 때 `fetch`나 `JSON.parse`를 쓰지 않는다.

## 5.4. localStorage 저장 단위

기능마다 키를 나눈다. 각 키의 값은 JSON 문자열이다.

| 저장 키 | 값의 모양 | 기본값 | 관련 기능 |
|---|---|---|---|
| `ootd_products` | `{ products: [의류], nextId: 숫자 }` | 저장 없음(= mock 데이터 사용) | F-12, F-18, F-23~F-27 |
| `ootd_cart` | `[장바구니 항목]` | `[]` | F-06~F-09, F-12 |
| `ootd_orders` | `[주문]` | `[]` | F-12, F-13, F-18 |
| `ootd_wishlist` | `[의류 번호]` | `[]` | F-16 |
| `ootd_recent_searches` | `[검색어]` | `[]` | F-20 |
| `ootd_restock_alerts` | `[알림 신청]` | `[]` | F-28, F-29 |

`nextId`는 다음에 등록할 의류 번호다. 삭제한 번호는 다시 쓰지 않는다(처음 값은 mock 데이터의 가장 큰 번호 + 1 = 117).

### 함께 바뀌어야 하는 저장 (F-12)

주문은 **주문 내역 추가 · 장바구니 비우기 · 재고 차감**이 한꺼번에 반영되어야 한다. 키가 나뉘어 있으므로 다음 순서를 지킨다.

1. 세 가지의 저장 내용을 각각 계산만 해 둔다(아직 쓰지 않는다).
2. `writeStorageAll`로 세 키를 잇달아 쓴다. 도중에 실패하면 **이미 쓴 키를 원래 값으로 되돌린다.**
3. 저장에 성공했을 때만 화면 상태를 바꾸고 주문 완료 화면으로 이동한다.

## 5.5. 장바구니 항목 — CART_ITEM

| 항목명 | 자료형 | 필수 | 예시 | 설명·검증 규칙 |
|---|---|---|---|---|
| `productId` | number | 필수 | 1 | 의류 번호 |
| `size` | string | 필수 | `M` | 담을 때 선택한 사이즈 |
| `quantity` | number | 필수 | 2 | 1~99의 정수 |

**같은 `productId`라도 `size`가 다르면 다른 항목이다.** 둘 다 같은 항목은 하나만 두고 수량을 합산한다.

상품명·사진·가격은 `productId`로 의류 데이터를 찾아 표시하고, 장바구니에는 금액을 저장하지 않는다.

| 표시값 | 계산 방법 |
|---|---|
| 항목별 금액 | 현재 판매 가격 × `quantity` |
| 주문 상품 금액 | 항목별 금액의 합계 |
| 공통 헤더 숫자 | `quantity`의 합계 (항목 수가 아님) |

삭제된 의류이거나 의류의 사이즈 목록에 없는 사이즈는 **구매 불가** 항목으로 표시하고 삭제만 허용하며, 그 항목이 있으면 주문을 막는다. 담은 수량이 재고보다 많으면 '재고 부족(남은 수량 N개)'을 표시하고 역시 주문을 막는다.

## 5.6. 주문 — ORDER

| 항목명 | 자료형 | 필수 | 예시 | 설명·검증 규칙 |
|---|---|---|---|---|
| `id` | string | 필수 | `26092100000001` | 주문일(YYMMDD) + 그날 순번 8자리. 중복 금지 |
| `orderedAt` | string | 필수 | `2026-09-21 14:30` | 주문 일시(YYYY-MM-DD HH:mm) |
| `status` | string | 필수 | `paid` | `paid` `shipping` `delivered` `cancelled` |
| `items` | array | 필수 | 아래 | 주문 항목, 최소 1개 |
| `shipping` | object | 필수 | 아래 | 주문 당시 배송 정보 |
| `shippingFee` | number | 필수 | 0 | 배송비 기능 미구현이므로 항상 0 |
| `totalPrice` | number | 필수 | 253000 | 항목별 금액 합계 + `shippingFee` |
| `cancelledAt` | string | 선택 | `2026-09-21 15:02` | 주문을 취소할 때 기록한다 |

주문 상태 이름은 `mocks/orders.js`의 `orderStatusLabels`에서 가져온다(주문 완료 / 배송중 / 배송 완료 / 주문 취소). 새 주문은 항상 `paid`로 저장하며, `shipping`·`delivered`는 화면 표시용 값이다.

### 주문 항목 — ORDER_ITEM

| 항목명 | 자료형 | 필수 | 예시 | 설명 |
|---|---|---|---|---|
| `productId` | number | 필수 | 1 | 구매한 의류의 번호 |
| `brand` | string | 필수 | 미쏘 | 주문 시점의 브랜드 |
| `name` | string | 필수 | 빈티지 리본 레이스 탑 | 주문 시점의 상품명 |
| `size` | string | 필수 | `S` | 주문한 사이즈 |
| `price` | number | 필수 | 27000 | 주문 시점의 정가 |
| `discountRate` | number | 필수 | 0 | 주문 시점의 할인율 |
| `salePrice` | number | 필수 | 27000 | 주문 시점의 판매 가격 |
| `quantity` | number | 필수 | 2 | 1~99의 정수 |
| `totalPrice` | number | 필수 | 54000 | `salePrice` × `quantity` |

주문 시점 정보를 복사해 두는 이유는 과거 주문 보존이다. 이후 가격·할인율이 바뀌거나 의류가 삭제되어도 주문 기록은 그대로 표시하며 금액을 다시 계산하지 않는다. 사진은 복사하지 않고 `productId`로 현재 의류에서 찾아 표시하며, 찾지 못하면 빈 칸으로 둔다.

### 배송 정보 — SHIPPING

| 항목명 | 자료형 | 필수 | 예시 | 설명·검증 규칙 |
|---|---|---|---|---|
| `name` | string | 필수 | 홍길동 | 앞뒤 공백 제거 후 빈 값 금지 |
| `phone` | string | 필수 | `010-1234-5678` | 문자열로 저장. 형식 검사 없음 |
| `address` | string | 필수 | 서울시 ○○구 ○○로 00 | 직접 입력한 가상 주소, 빈 값 금지 |

### 상태 규칙

| 상황 | 저장 규칙 |
|---|---|
| 주문 완료 | `status = paid`, `cancelledAt` 없음 |
| 모의 취소 (F-18) | `status = cancelled`, `cancelledAt`에 취소 일시 |

취소해도 `items`·`shipping`·금액·`orderedAt`은 그대로 둔다. 주문을 지우거나 장바구니로 자동 복원하지 않는다. 취소하면 주문 수량만큼 재고를 되돌리고, 재고가 0에서 1 이상이 되면 `restockedAt`을 기록한다. 삭제된 의류나 없어진 사이즈는 되돌리지 않는다.

## 5.7. 추가 기능 데이터

### 좋아요 — `ootd_wishlist`

의류 번호의 숫자 배열이다. 등록 순서를 유지하며 중복을 만들지 않는다. 사이즈와 무관하게 의류 단위로 등록한다.

```json
[3, 1, 7]
```

### 최근 검색어 — `ootd_recent_searches`

앞뒤 공백을 제거한 검색어 문자열 배열이다. 최신순으로 맨 앞에 넣고 최대 10개를 유지한다. 영문 대소문자만 다른 검색어는 같은 검색어로 보고, 빈 검색어는 저장하지 않는다.

```json
["니트", "디키즈"]
```

### 재입고 알림 신청 — `ootd_restock_alerts`

| 항목명 | 자료형 | 필수 | 예시 | 설명 |
|---|---|---|---|---|
| `productId` | number | 필수 | 23 | 신청한 의류 번호 |
| `size` | string | 필수 | `XL` | 신청한 사이즈 |
| `requestedAt` | string | 필수 | `2026-09-21 10:07` | 신청 일시 |
| `notified` | boolean | 필수 | `false` | 팝업으로 알렸는지 여부 |

같은 의류·같은 사이즈의 `notified: false` 신청이 있으면 새로 만들지 않는다. 팝업을 띄운 신청은 `notified: true`로 저장해 다시 띄우지 않는다. 신청한 의류가 삭제되었거나 사이즈가 없어졌으면 팝업 없이 `true`로 바꾼다.

## 5.8. 탐색 조건과 화면 상태

### 주소에 담는 탐색 조건 (S-02)

새로고침해도 같은 결과를 보여 주기 위해 목록의 조건은 주소 쿼리에 넣는다. localStorage에는 저장하지 않는다.

| 이름 | 값 | 설명 |
|---|---|---|
| `gender` | `men` `women` `unisex` | 없으면 전체 목록(CLOTHES) |
| `brand` | 브랜드 이름 | 없으면 전체 브랜드 |
| `season` | `봄` `여름` `가을` `겨울` `사계절` | 없으면 전체 계절 |
| `category` `group` `item` | 분류 이름 | 고른 단계까지만 넣는다 |
| `q` | 검색어 | 없으면 검색하지 않은 상태 |
| `sort` | `registered` `latest` `price` `discount` | 성별 페이지는 없으면 등록순, CLOTHES는 없으면 무작위 |

예: `/products?gender=women&brand=미쏘&season=여름&category=상의&sort=price`

### 리액트 state로만 두는 값

| 상태 | 사용 위치 | 역할 |
|---|---|---|
| 입력 중인 검색어 | S-02 | 확정 전 검색창 값 |
| 페이지 번호 | S-02 | 한 페이지 12개, 조건이 바뀌면 1로 |
| 무작위 순서표 | S-02(CLOTHES) | 화면에 들어올 때마다 새로 섞는다 |
| 선택 사이즈·구매 수량 | S-03 | 다른 의류를 열면 선택 안 함·1로 시작 |
| 배송 입력값·항목별 오류·제출 중 여부 | S-05 | 주문 중복 제출 방지 포함 |
| 관리자 목록의 검색어·정렬·상태·페이지 | S-09 | 칸 제목에서 고른 조건 |
| 팝업·드롭다운 열림 여부 | 공통 | 화면 안에서만 쓰는 상태 |

## 5.9. 데이터를 다루는 코드

화면이 localStorage에 직접 쓰지 않고, 아래 파일을 통해서만 읽고 쓴다.

| 파일 | 역할 |
|---|---|
| `utils/storage.js` | `readStorage`(읽기·구조 검사), `writeStorage`(쓰기), `writeStorageAll`(여러 키 한 번에 쓰기·실패 시 되돌리기), `clearStorage`(초기화) |
| `utils/price.js` | `getSalePrice`(판매 가격), `SHIPPING_FEE`(0) |
| `utils/sort.js` | 정렬 기준 목록과 정렬 계산, 무작위 순서표 |
| `context/ProductsContext.jsx` | 의류·재고 읽기, 재고 증감, 등록·수정·삭제, 주문용 저장 내용 준비 |
| `context/CartContext.jsx` | 담기·수량 변경·삭제, 주문용 저장 내용 준비 |
| `context/OrdersContext.jsx` | 주문 목록, 주문 저장 내용 준비, 주문 취소 |
| `context/WishlistContext.jsx` | 좋아요 등록·해제 |
| `context/RestockAlertsContext.jsx` | 재입고 알림 신청·표시 여부 |
| `components/SearchBox.jsx` | 최근 검색어 저장·삭제 |

저장하는 함수는 성공 여부를 돌려주고, 화면은 **성공한 경우에만** 완료 안내나 이동을 한다.

## 5.10. 불러오기·저장 흐름 (F-14)

**시작·새로고침할 때**

1. 각 키를 읽어 `JSON.parse`하고 구조를 검사한다.
2. 키가 없으면 기본값으로 시작한다(의류는 mock 데이터).
3. 검사에 실패하면 **원본을 지우지 않고** 그 데이터만 '읽지 못함'으로 표시한다.
4. 읽지 못한 데이터가 있으면 헤더 아래에 안내 줄을 띄우고, 저장이 필요한 동작을 막는다.
5. 사용자가 초기화를 선택하고 확인 창에서 확인해야만 그 키를 지우고 기본값으로 시작한다.

**사용자가 데이터를 바꿀 때**

1. 기존 배열·객체를 직접 바꾸지 않고 다음 값을 만든다.
2. 먼저 저장한다.
3. 저장에 성공했을 때만 화면 상태를 바꾸고 안내한다.
4. 실패하면 기존 상태를 유지하고 실패를 안내한다.

## 5.11. 데이터 변경 예시

| 동작 | 변경 전 | 변경 후 |
|---|---|---|
| 같은 의류·같은 사이즈 추가 | `{1, M, 1}` | 2개 추가 시 `{1, M, 3}`, 항목은 하나 |
| 같은 의류·다른 사이즈 추가 | `{1, M, 1}` | `{1, M, 1}`, `{1, L, 1}` 두 항목 |
| 수량 초과 추가 | `{1, M, 98}` | 2개 추가 거부, 98 유지 |
| 재고 초과 추가 | 재고 3, `{23, XL, 2}` | 2개 추가 거부, '추가로 담을 수 있는 수량은 1개입니다(재고 3개)' 안내 |
| 전체 주문 | 장바구니 2항목 | 주문 항목에 주문 시점 정보 복사, `ootd_cart`는 `[]`, 재고 차감 (세 키를 한 번에 저장) |
| 주문 취소 | `paid` | `cancelled`와 취소 일시, 재고 복원, 원래 금액 유지 |
| 관리자 할인율 변경 | `discountRate: 0` | `ootd_products`에 20으로 저장. 장바구니 금액은 다시 계산, 완료된 주문 금액은 그대로 |
| 관리자 재입고 | `stock.XL = 0` | `stock.XL = 10`, `restockedAt.XL`에 일시 기록 → 신청자에게 5초 뒤 팝업 |

## 5.12. 데이터 검증 규칙

| 대상 | 검사할 내용 | 실패 시 처리 |
|---|---|---|
| 의류 데이터 | 배열 여부, `id`·`name`·`price`·`sizes`·`stock` 존재와 자료형 | 읽지 못함으로 표시, 저장이 필요한 동작 금지 |
| 장바구니 | `productId` 정수, `size` 문자열, `quantity` 1~99 정수 | 읽지 못함으로 표시 |
| 장바구니 참조 | 현재 의류 존재 여부, 사이즈 존재 여부, 재고 초과 여부 | 구매 불가·재고 부족으로 표시하고 주문 차단 (구조 오류와 구분) |
| 주문 | 배열 여부, `id`·`orderedAt` 문자열, `items` 배열 | 읽지 못함으로 표시 |
| 좋아요 | 숫자 배열 여부 | 읽지 못함으로 표시 |
| 재입고 알림 | `productId` 정수, `size` 문자열, `requestedAt` 문자열, `notified` 참/거짓 | 읽지 못함으로 표시 |
| 최근 검색어 | 문자열 배열 여부 | 빈 목록으로 시작 |
| 입력값 | 수량 1~99 정수, 가격·재고 0 이상 정수, 할인율 0~90 정수, 배송 정보 빈 값 금지 | 항목별 안내 후 저장하지 않음 |
| 저장 처리 | 쓰기 성공 여부 | 화면 상태 변경·성공 안내·완료 이동 금지 |

주문 검증은 저장된 금액으로 한다. 현재 의류 가격과 다르다는 이유로 정상 과거 주문을 오류로 보지 않는다.
